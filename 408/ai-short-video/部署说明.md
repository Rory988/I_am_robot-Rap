## ⚠️ 先说一个重要更正：满血权重不是 42.5GB，是约 123.6GB

之前口头估的「H3 权重约 42.5GB」对应的是**官方模板默认的量化套装**（pruned int8 主干 21.0GB + nvfp4 文本编码器 15.7GB + int8 视频 VAE 2.8GB + fp32 音频 VAE 0.6GB + turbo LoRA 2.0GB ≈ 42.1GB）。

**BF16 满血全套**（本笔记本下载的）经 HuggingFace 官方 API 逐文件核对为：

| 文件 | 作用 | 精确字节 | 约 GB |
|---|---|---|---|
| `diffusion_models/minimax_h3_fl2va_bf16.safetensors` | 主干 DiT（图生/文生视频） | 66,280,487,368 | 66.28 |
| `text_encoders/qwen3vl_32b_minimax_h3_bf16.safetensors` | 文本编码器 Qwen3-VL 32B | 51,506,295,256 | 51.51 |
| `vae/minimax_h3_video_vae_fp16.safetensors` | 视频 VAE | 5,207,808,496 | 5.21 |
| `vae/minimax_h3_audio_vae_fp32.safetensors` | 音频 VAE | 605,254,808 | 0.61 |
| `loras/minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors` | 可选 8 步快速 LoRA | 1,956,193,000 | 1.96 |
| **合计** | | | **125.56（不含 LoRA 123.60）** |

影响：他的 Google Drive 是 5TB，放得下；G4 本地盘 235.7GB 也够，但本方案按 EasyColab 的做法把权重直接存云盘软链使用。首次下载时间与 CU 消耗要按 124GB 量级重新估算（见文末）。

**显存账**：权重总和约 124GB > G4 显存 95.6GB，所以运行时 ComfyUI 必然要把一部分（主要是文本编码器）卸载到系统内存——G4 有 176.9GB 内存，装得下；EasyColab 的 H3 方案本身就是「文本编码器 + DiT 常驻高速内存」的设计。代价是首次加载慢、生成速度可能低于纯显存驻留，此点未实测（见未验证项 2）。

1. **EasyColab 仓库与服务端笔记本源码**

   - 注意区别：EasyColab 的「H3 BF16 满血」独立引擎走的是 **DiffSynth-Studio + 官方权重仓 MiniMaxAI/MiniMax-H3**（同在该笔记本源码中核对），不是 ComfyUI；其 ComfyUI 预置里的是 H3 **Turbo** 工作流。本笔记本按需求走 ComfyUI 原生节点路线，权重用 Comfy-Org 重打包版（与官方模板的模型槽位一一对应）。
2. **ComfyUI 官方文档（原生 H3 教程）**：https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native 与总览 https://docs.comfy.org/tutorials/video/minimax/minimax-h3 —— 核对：H3 为 ComfyUI **0.30.0+ 原生支持、无需自定义节点**；模板含 T2V/I2V/R2V；原生画布 768px 短边、上限 768×1344、32 的倍数；时长按 17k+5 帧 @24fps 对齐；默认 20 步，turbo 8 步；首帧会被拉伸到画布比例（关键帧须本身 9:16）。

4. **权重仓库与精确体积（HuggingFace 官方 API）**：https://huggingface.co/Comfy-Org/MiniMax-H3 ，体积取自其 tree API（`/api/models/Comfy-Org/MiniMax-H3/tree/main/diffusion_models`、`text_encoders`、`vae`、`loras` 四个端点逐个打开核对字节数）。官方原始权重仓为 https://huggingface.co/MiniMaxAI/MiniMax-H3（498GB 全量，不要整仓下载）。
5. **cloudflared 官方发布**：https://github.com/cloudflare/cloudflared/releases —— 经 GitHub API 核对最新版（2026.10.7）资产命名规律含 `cloudflared-linux-amd64`，笔记本用官方 `releases/latest/download/cloudflared-linux-amd64` 直链。

## 未验证项（无法在本地替他实测，首次真跑时要盯）

1. **未用他的 Colab Pro 账号实跑过全流程**：本机无其账号权限。笔记本逻辑全部按上列来源组装并通过 Python 语法校验，但「在 Colab G4 上从头跑通」这一步只能等他首次运行时验证；若某格报错，把报错原文发回即可定位。
2. **BF16 全套在 G4 上的实际速度与稳定性未实测**：124GB 权重靠显存+内存混合驻留，ComfyUI 的动态卸载能否顺畅跑完 768×1344、20 步、197 帧（8 秒）没有实测数据。若显存溢出或慢到不可用，回退顺序：①文本编码器换 `qwen3vl_32b_minimax_h3_int8_convrot.safetensors`（27.1GB）；②仍不行再把主干换 `minimax_h3_fl2va_pruned_bf16.safetensors`（40.2GB）；③最后才考虑模板默认的量化套（约 42GB）。回退文件的下载格改动只需替换 FILES 列表。
3. **首次下载时长是估算**：124GB 经 Colab 网络 + 写入 Drive 的实际吞吐未实测，下文耗时按常见区间估，不是承诺。
4. **cloudflared 直链未逐字打开验证**：只核对了官方 releases 的资产命名规律；`releases/latest/download/...` 是 GitHub 官方跳转机制。若该格下载失败，改法：到 releases 页选定版本拼 `releases/download/<版本>/cloudflared-linux-amd64`，或临时改用 Gradio share 隧道。
5. **许可证属地提示（合规、未核实）**：据模型卡的二手报道（iimagined、minimax3 的 H3 指南），MiniMax H3 社区许可证将美国、欧盟、英国、韩国排除在本地运行授权之外；Colab 运行时机房由 Google 分配、很可能在美国。此点未向 MiniMax 官方逐字核实，仅作风险提示，是否介意由用户判断。
6. **ComfyUI 版本漂移**：第 3 格克隆的是 ComfyUI 最新 master，模板 JSON 标注版本为 0.33.0；官方模板与新版 ComfyUI 一般向后兼容，但未实测锁定版本。
